proTES can now account the resources that the tasks of each user used and
export them as Tool Execution Reports of ELIXIR Compute (format 0.0.2),
without personal data, let apps with tokens of their own (service clients)
create and own tasks, and request an access token of its own for each TES
instance, all opt-in. It moves to FOCA 0.23, whose image fixes a high
vulnerability of the image of 0.6.0: deployments with a single trusted
issuer must set its `namespace: ""` to keep the owners of their tasks, and
the worker of the Helm chart gets readiness and liveness probes by
default, which changes upgrades of the chart: read the [upgrade
steps](https://protes.readthedocs.io/en/v0.7.0/upgrading/#to-version-070)
first. This release was tested against Funnel 0.12.3 (TES 1.1, by label and
from its service info), TESP-API 0.2.0 with Pulsar 0.14.16 (TES 1.0) and
tesk-api 1.1.0 with the taskmaster and filer v0.10.6 (TES 1.0) in CI;
tesk-api 2.0.0 (TES 1.1) was not tested. See the
[documentation](https://protes.readthedocs.io/en/v0.7.0/) for details.

## Breaking changes

- FOCA 0.23: owners of tasks are namespaced by their issuer
  (`<issuer>|<sub>`) also with a single trusted issuer, so deployments
  with one issuer must set its `namespace: ""` to keep the owners of their
  tasks, their limits and their accounting records; rules of overlays that
  name bare users stop the start otherwise (see the [upgrade
  steps](https://protes.readthedocs.io/en/v0.7.0/upgrading/#to-version-070))
  (#522, #523)
- Tasks whose `gateway.backends` is an `allow` of identifiers only, none of
  which names a TES instance of proTES, are rejected with `400`
  (`invalid-backends`) instead of `503`; on endpoints that require a
  token, anonymous requests with too large bodies get `401` instead of
  `413` (FOCA 0.23) (#522, #523)
- The worker of the Helm chart has a readiness and a liveness probe by
  default (`celery inspect ping` through the broker): upgrades wait until the
  new worker answers, a worker that doesn't answer for 10 minutes is
  restarted, and values that set `worker.readinessProbe` or
  `worker.livenessProbe` are merged into the new probes; brokers without
  Celery's remote control (e.g., Amazon SQS) need both set to `null` (see the
  [upgrade
  steps](https://protes.readthedocs.io/en/v0.7.0/upgrading/#to-version-070))
  (#504, #505)

## Features

- Opt-in accounting of resource usage per user
  (`custom.accounting.enabled`): the Celery workers record the run time and
  the requested resources of each task that finishes at its TES instance, and
  admins get the totals per user at `GET /usage` (rule `admins-get-usage`)
  (#459, #490)
- Execution reports: admins get the usage records as Tool Execution Reports
  of ELIXIR Compute, format version 0.0.2, at `GET /usage/reports` (rule
  `admins-get-usage-reports`), for completed tasks of images in trusted
  namespaces, with the providers and locations of
  `custom.accounting.reports`; reports hold no user identifiers and no
  details of tasks, no versions from tags of images given with a digest
  (which are unchecked), and identifiers of the tool from tags of the task
  only for the tags listed in `custom.accounting.reports.tags` (by default
  `biotools_id` and `rrid`) (#502, #503; #520, #516)
- Service clients (opt-in): apps with their own client-credentials tokens,
  listed by issuer and client ID with the role user, can create tasks and
  list, read and cancel their own; a client's ID is accepted as audience
  only for its own service tokens, and service tokens with groups are
  rejected (#517, #521)
- Opt-in access tokens per TES instance:
  `custom.tes.client_credentials.audience_parameter` (`resource` or
  `audience`) requests a token for each TES instance, for its `audience` or
  else its URL, so that TES instances with different audiences can't use
  their tokens at each other (entries with the same `audience` share a
  token) (#397, #488)

## Security

- The image is built on FOCA 0.23.0, whose base image has libzstd1
  1.5.7+dfsg-1+deb13u1, which fixes CVE-2026-124851 (high) of the image of
  0.6.0; on endpoints that require a token, FOCA checks it before reading
  the body, so anonymous clients can't make proTES read request bodies
  (#522, #523)
- The image has dnspython 2.9.2, which fixes CVE-2026-128089 (high) of
  dnspython 2.9.1 in the image of 0.6.0 (#491)
- Lint rules find disabled TLS verification also in calls on sessions,
  decoding of JSON Web Tokens with unsafe algorithms and unsafe YAML loads;
  they find nothing in the code (#500, #499)
